# I2 — запуск по CSV

Код читает `DATA_DIR/questions.csv` в UTF-8. Если переменная не задана, используется каталог `data`. Результат `submission.csv` записывается в рабочий каталог с колонками `id,answer` и исходным порядком записей. Ответ должен содержать хотя бы один непробельный символ. Максимальная длина ответа — 10 000 символов.

Перед обработкой скрипт проверяет весь входной файл, включая пустые значения и повторяющиеся ID. Каждому вызову обработчика передаётся исходная ячейка `question`, включая переносы строк. Общий обработчик восстанавливает контекст отдельно для каждой строки.

Обработка идёт последовательно. В платформенном режиме при ошибке отдельного вопроса или недопустимом ответе скрипт записывает резервный ответ и продолжает прогон. В журнал попадают позиция записи и тип ошибки. Скрипт заменяет `submission.csv` только после записи всех ответов. Если входной файл некорректен, результат не удалось записать или обработчик вернул ошибку для всех вопросов, запуск завершается с ошибкой, а предыдущий файл сохраняется. Функция `run_submission` по умолчанию работает в строгом режиме.

## Проверка на синтетических данных

Из корня репозитория:

```sh
python3 -B -m unittest discover -s tests -v
repo_dir="$PWD"
demo_dir="$(mktemp -d)"
printf 'id,question\n007,"Первая реплика\nВторая реплика"\n2,Другой вопрос\n' > "$demo_dir/questions.csv"
(
    cd "$demo_dir" || exit
    DATA_DIR="$demo_dir" python3 -B "$repo_dir/solution.py" --demo
    cat submission.csv
)
```

`--demo` выдаёт фиксированные синтетические ответы для проверки формата. `run_submission(data_dir, answer_question)` принимает асинхронный обработчик `str -> str`. Входная строка может включать весь диалог. Обычный запуск загружает `DATA_DIR/knowledge-base.zip` и передаёт релевантные фрагменты модели через API организаторов. См. [сборку ZIP и запуск](I3_SUBMISSION.md).
