# S1 · Черновик общего контракта

Версия предложения `0.1`. Документ задаёт стык консультанта, поиска, веба и CSV для обсуждения в [S1 #2](https://github.com/Alexeyokey/casemtc/issues/2). Рабочий локальный прототип показывает часть этого сценария через HTML-формы. Маршруты `/api/v1` ниже предлагаются для командной реализации.

## Ядро и адаптеры

`ConsultationEngine.consult(history, client_context)` получает только текущий диалог в порядке реплик. Последняя реплика принадлежит пользователю. `client_context` содержит подтверждённые клиентом сведения о задаче и объекте. Неизвестное остаётся пустым, а предположения не переходят в факты. Формат состояния и способ его обновления нужно согласовать с Максимом.

Ядро возвращает `text`, `action`, при необходимости `clarification` или `lead_draft`, а также диагностику отдельно. Варианты `action` сохраняют имена из прототипа.

- `answer` — полезный ответ, в том числе продолжение консультации после отказа от контактов.
- `clarify` — вопрос о факте, который влияет на рекомендацию. `clarification` содержит его текст и при необходимости ключ поля.
- `offer_contact` — предложение связаться со специалистом и черновик резюме. Заявка появляется после явного запроса сохранения из веба.

Ядро работает без HTTP, SQLite и CSV. Веб хранит историю, идентификаторы ходов и заявки. CSV передаёт историю из одной строки, вызывает то же ядро и записывает `id,answer`. Каждый ID CSV начинает независимый диалог.

## Источники и отладка

`Evidence` на входе в генерацию содержит `id`, `path`, `heading` и `text`. В отладке `retrieved` перечисляет найденные разделы с их ID, файлом и заголовком. `used_source_ids` содержит ссылки модели, проверенные на принадлежность к `retrieved`. Фактичность утверждения проверяется отдельно. Влад подтверждает стабильность ID при неизменном корпусе.

Пользовательский ответ содержит текст, действие и данные, необходимые для интерфейса. `timings_ms` хранит время поиска, модели и всего хода. Пропущенный этап отмечается `null`. Debug доступен отдельно по разрешению, без сырого промпта, ключей и контактов. Полный архив выдаётся по отдельному запросу с проверкой доступа.

## Предложение по HTTP API

| Маршрут | Назначение |
|---|---|
| `POST /api/v1/sessions` | Создать новый диалог и вернуть `session_id`. |
| `POST /api/v1/sessions/{session_id}/turns` | Принять `request_id` и `message`. Вернуть `202` и состояние хода. |
| `GET /api/v1/sessions/{session_id}/turns/{request_id}` | Получить текущее состояние или окончательный результат. |
| `POST /api/v1/sessions/{session_id}/turns/{request_id}/cancel` | Отменить незавершённый ход или вернуть уже зафиксированный результат. |
| `POST /api/v1/sessions/{session_id}/close` | Закрыть активный диалог, сохранив архив. Новый диалог получает отдельный ID. |
| `GET /api/v1/sessions/{session_id}/archive` | Получить историю текущей или закрытой сессии при наличии доступа. |
| `POST /api/v1/sessions/{session_id}/lead` | Сохранить заявку по явно подтверждённой форме. |
| `GET /api/v1/sessions/{session_id}/turns/{request_id}/debug` | Получить отладку конкретного хода при наличии доступа. |

`session_id` выдаёт сервер. `request_id` создаёт веб и сохраняет для повторной отправки. Повтор с тем же ID и содержимым возвращает уже известное состояние. Другой текст с тем же ID даёт `409 request_conflict`. Для черновика предлагаем один незавершённый ход на сессию.

Переходы хода идут из `queued` в `running`, затем в `completed`, `failed` или `cancelled`. Завершение и отмена фиксируются атомарно. Если ответ уже сохранён, отмена возвращает его состояние. При ошибке или отмене частичный ответ не попадает в историю, передаваемую ядру. Базовый клиент может опрашивать `GET`. С Катриной нужно решить, нужен ли SSE и какие события показывать до завершения.

## Заявка

Ядро формирует краткое резюме. Веб привязывает к сохранённой версии резюме `offer_id` и возвращает оба поля в `lead_draft`. Клиент видит резюме до подтверждения. Устаревший черновик даёт `409 stale_offer`. Повтор той же сохранённой заявки возвращает её ID.

Для сохранения нужен валидный телефон. Имя и компания запрашиваются, но могут остаться `null`. При отказе от всех контактов консультация и сохранение истории продолжаются. В интерфейсе «Заявка сохранена» означает запись заявки. Доставку менеджеру подтверждает только отдельный механизм передачи.
