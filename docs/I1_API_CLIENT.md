# I1 — клиент API организаторов

Задача: [#4](https://github.com/Alexeyokey/casemtc/issues/4). Реализован транспортный клиент; это ещё не консультант и не законченный платформенный `solution.py`.

Генерация, эмбеддинги и реранкер используют один адрес прокси. Форматы взяты из предоставленного организаторами `sample_submission.zip`, переменные — из [регламента](https://docs.google.com/document/d/1wZsqH4xXZXwjiAJCtFQGjTaLxEU3D_tMCSw0yXcbQ0U/edit). Пакет `httpx==0.28.1` входит в выданный список зависимостей. Исходные материалы и БЗ в Git не скопированы.

## Проверка без прокси

Python 3.11 или новее, рабочая папка — корень репозитория:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m examples.i1_offline
```

Ключи и `.env` для этого не нужны. Все тексты и ответы синтетические. Offline-пример использует `MockTransport` без сети и печатает `real_proxy_checked: false`. Тесты дополнительно поднимают настоящий HTTP-сервер на `127.0.0.1` со случайным свободным портом. Они не обращаются к внешним API и не читают БЗ.

Проверяются три маршрута и payload, альтернативные имена переменных, переставленные эмбеддинги, форматы реранкера, 401/429/5xx, ошибки соединения, медленные/оборванные ответы, общий бюджет и очередь, отмена, редиректы и отсутствие ключей/текста клиента в метриках и сообщениях ошибок. Это проверка реализации на контрактных фикстурах, а не доказательство поведения настоящего сервиса.

## Интерфейс для остальных модулей

Корневой `organizer_api.py` не зависит от HTTP-сервера приложения, CSV, RAG и состояния консультации. Это позволяет I3 включить модуль в плоский ZIP без переписывания импортов.

```python
import asyncio
import time
from organizer_api import APIConfig, OrganizerClient, AuthenticationError, OrganizerAPIError

async def main():
    # Таймер запуска должен начаться ДО индексации/другой подготовки.
    deadline = time.monotonic() + 1100
    config = APIConfig.from_env()
    async with OrganizerClient(config, deadline=deadline) as client:
        result = await client.chat([
            {"role": "system", "content": "Инструкция консультанта из общего ядра."},
            {"role": "user", "content": "Вопрос клиента."},
        ])
        print(result.text)  # Пользовательский ответ; не диагностический лог.
        vectors = await client.embed(["фрагмент один", "фрагмент два"])
        ranks = await client.rerank("запрос", ["фрагмент один", "фрагмент два"], top_n=1)
        # vectors.vectors соответствует порядку входа, без нормализации.
        # ranks.ranks содержит index исходного документа и score провайдера,
        # либо score=None, если сервер вернул только индексы, как допускает образец.

asyncio.run(main())
```

- **I2 / CSV:** один event loop и один клиент на запуск; независимые вопросы можно запускать через `asyncio.gather`, сам клиент ограничивает число HTTP-запросов. Контекст между ID клиент не хранит. Повторное создание клиента для каждой строки обнуляет общий бюджет и не рекомендуется.
- **R3/R4:** `embed` и `rerank` принимают один batch не более `API_MAX_BATCH_SIZE`; разбивать большой корпус на batches должен вызывающий модуль. Необязательные этапы могут явно деградировать до лексического поиска. Клиент не делает это молча и не выдаёт случайный ответ при ошибке.
- **C2/C3:** роли текстовых сообщений `system/user/assistant/developer`, содержимое — непустая строка. Поддержка роли `developer` конкретным прокси ещё требует проверки. `ChatResult.text` отделён от reasoning; возвращается только признак наличия reasoning, не его содержание. `finish_reason=length` даёт ошибку `truncated_response`, не успешный ответ. Вызовы tools, streaming/SSE и формат JSON Schema в I1 не реализованы: streaming интерфейса приложения можно строить поверх собственного backend отдельно.
- **S2/S4:** клиент асинхронный, его нужно `await`-ить. Один экземпляр используется в одном event loop. `client.metrics` — последние 1000 безопасных записей: операция, результат, попытки, время, HTTP-статус и код ошибки. Нет URL, заголовков, ключей, текста сообщений/ответа и сырых тел ошибок. Привязку к `session_id/request_id` добавляет backend. Не сериализовать конфигурацию через `dataclasses.asdict`: ключи нужны клиенту и есть в объекте, хотя скрыты в `repr`.
- **I3:** перенести корневой модуль и закреплённый `requirements.txt`; тесты и examples в платформенный ZIP не нужны. Здесь ещё нет exporter или `solution.py` — это I2/I3.

Использовать `async with` и завершать задачи до закрытия клиента. Отмена `asyncio.CancelledError` передаётся вызывающему коду, активный запрос закрывается; слот параллелизма освобождается. Не использовать экземпляр в разных потоках/event loops. Синхронному внешнему скрипту достаточно одного `asyncio.run(main())`; внутри работающего FastAPI-loop новый `asyncio.run` не вызывают.

Эмбеддинги восстанавливаются по целочисленному `index`; если индексов нет во всём batch, используется порядок ответа, как в образце. Смесь индексированных и неиндексированных строк, дубли, пропуски, разные размерности, NaN/Infinity отклоняются. Реранкер принимает `results` или `data`, сохраняет порядок ранжирования, проверяет уникальность и диапазон индексов. `relevance_score`/`score` необязателен; если указан, должен быть конечным числом. Отсутствующий score не выдумывается. Эти варианты пока проверены на фикстурах, не на настоящем прокси.

## Переменные окружения

Клиент читает переданное окружение, но сам не загружает `.env`. `.env.example` — образец для среды запуска/будущего Compose; на платформе значения предоставляет организатор. При отсутствии обязательных значений клиент сразу даёт безопасную `ConfigurationError` без вывода значения. Невалидные числа не заменяются молча настройками по умолчанию.

| Назначение | Имена в порядке приоритета | По умолчанию |
|---|---|---|
| Адрес | `LLM_BASE_URL`, `OPENAI_BASE_URL`, затем `BASE_URL` из образца | Обязателен |
| Основной ключ | `LLM_API_KEY`, `OPENAI_API_KEY` | Обязателен |
| Генеративная модель | `LLM_MODEL`, `OPENAI_MODEL`, `GEN_MODEL` | Обязательна; имя не зашито в код |
| Эмбеддер | `EMB_MODEL` | `baai/bge-m3` из образца |
| Реранкер | `RERANKER_MODEL` | `qwen/qwen3-reranker-8b` из образца |
| Необязательные отдельные ключи | `EMBEDDER_API_KEY`, `RERANKER_API_KEY` | Основной ключ |
| Генерация | `TEMPERATURE`, `MAX_TOKENS` | `0.0`, `2048` |
| Сколько результатов реранкера | `RERANKER_TOP_N` | `2`, не больше числа документов |
| Параллельные HTTP-запросы | `MAX_WORKERS` | `3`, клиент допускает `1..32` |
| Дополнительные попытки | `API_MAX_RETRIES` | `2`, клиент допускает `0..5` |
| Таймаут сетевой неактивности | `API_REQUEST_TIMEOUT_S` | `30` секунд; connect/pool не больше `5` |
| Бюджет одной операции целиком | `API_CALL_TIMEOUT_S` | `60` секунд |
| Общий оставшийся бюджет | `API_RUN_BUDGET_S` | `1100` секунд; максимум `1200` |
| Начальная пауза повторов | `API_RETRY_BACKOFF_S` | `0.5` секунды, экспонента до `5` секунд |
| Размер batch | `API_MAX_BATCH_SIZE` | `32` текста/документа |
| Максимум тела ответа | `API_MAX_RESPONSE_BYTES` | `8388608` байт тела без сжатия |

Пустые значения и буквальные самоссылки (`LLM_MODEL=LLM_MODEL`) пропускаются при выборе альтернативы, как в образце. Порядок приоритета официальных алиасов следует регламенту; `BASE_URL` — последний legacy fallback. Слеш `/v1` не дописывается автоматически: сохраняется префикс переданного адреса, к нему добавляется маршрут. URL с userinfo, query/fragment и неверным портом отклоняется. Ключ — непустой печатный ASCII без пробелов/переносов строк, без префикса `Bearer`.

Настройки `DATA_DIR`, `TOP_K`, `CHUNKER` и `PYTHONPATH` относятся к загрузке/поиску/среде, клиент их не присваивает себе. Вложенные параметры модели передаются явно:

```python
result = await client.chat(messages, extra_body={
    "chat_template_kwargs": {"enable_thinking": False},
})
```

Это пример механизма передачи. Поддержку указанного поля проверяем на прокси. Поля `model/messages/stream/temperature/max_tokens` зарезервированы, а для `temperature` и `max_tokens` есть явные аргументы метода. Нестандартные параметры задаются явно. Несериализуемые объекты, NaN/Infinity и чрезмерная вложенность приводят к `invalid_json_parameters` до обращения к API.

## Ошибки, повторы и время

`OrganizerAPIError` содержит только `code`, название операции, статус и число попыток. Не сохраняет тело ответа и объект HTTP-запроса. Ошибки не превращаются в фразу об отсутствии знаний — решение об ответе/деградации принимает ядро.

| Ситуация | Поведение |
|---|---|
| HTTP 401 | Отдельная `AuthenticationError`, без повторов и замены ключа. Сообщить организаторам |
| HTTP 400/403/404/422, редирект | Ошибка сразу; редиректам клиент не следует |
| HTTP 408/429/5xx, сетевой сбой, timeout | До `1 + API_MAX_RETRIES` попыток, пока хватает общего времени |
| `Retry-After` | Секунды или HTTP-дата; если ожидание не помещается в бюджет, ошибка без раннего повтора |
| Неверный JSON/схема, пустой или обрезанный ответ, слишком большое тело | Явная ошибка без повторов |
| Прокси прислал сжатый ответ или другое кодирование тела | `unsupported_content_encoding` без чтения тела и повторов |
| Отмена задачи | Не подавляется и не превращается в повтор |
| Общий бюджет или срок одной операции исчерпан | Нет новых запросов; активное ожидание отменяется |

Очередь семафора, сетевые операции, чтение ответа и паузы повторов находятся внутри одного абсолютного срока `asyncio.timeout`. Для HTTPX отдельно настроены сетевые таймауты; они сами по себе отслеживают неактивность, а не полный срок запроса. Поэтому медленная выдача по частям не обходит общий срок. Во время паузы между попытками слот параллелизма свободен.

Клиент запрашивает `Accept-Encoding: identity` и проверяет `Content-Encoding` до чтения ответа. Ограничение размера применяется к получаемым порциям тела. Это исключает распаковку сжатого ответа внутри HTTPX до проверки лимита.

1100 секунд — наш запас относительно письменных 20 минут, не новый лимит организаторов. Чтобы учесть предобработку, вызывающий код передаёт `deadline`, рассчитанный в самом начале запуска. На долгоживущем web-сервере этот бюджет заканчивается: S2 должен явно выбирать жизненный цикл клиента/бюджет для web, а не держать один экземпляр бесконечно. Ориентир Q&A 5–7 секунд не становится жёстким таймаутом клиента.

Внешние `HTTP_PROXY/HTTPS_PROXY`, системные ключи и редиректы автоматически не используются: `trust_env=False`, TLS-проверка HTTPX остаётся включённой. Вызовы сбоев генерации могут уже быть выполнены сервером до сетевого обрыва; повтор не гарантирует exactly-once и может повторно потратить вычисления. Для этих трёх операций нет побочных эффектов создания заявки; отправку заявки через этот retry-механизм не выполняем.

Подготовлена команда для будущей проверки на синтетических коротких текстах. Без `--live` она не делает запросов:

```sh
python -m examples.i1_live_check
# Только после получения организаторского окружения:
python -m examples.i1_live_check --live
```

При успехе проверяются три wire-контракта и печатаются безопасные метрики; содержание модели/ключи не печатаются. При первой ошибке команда останавливается. Такой smoke не доказывает качество RAG или итоговый балл. В рамках текущей I1 живой прокси не проверялся.
