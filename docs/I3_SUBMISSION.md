# Поиск по базе и сборка платформенного ZIP

`solution.py` читает `questions.csv` и `knowledge-base.zip` из `DATA_DIR`. Для каждой строки ядро восстанавливает текущую тему, ищет фрагменты и проверяет ответ модели. Критерии по источникам, числам и ограничениям описаны в [приёмке консультации](CONSULTATION_ACCEPTANCE.md).

## Собрать ZIP

Из корня репозитория выполните:

```sh
python3 -B scripts/build_submission.py --output /tmp/energytool-submission.zip
```

В архиве восемь файлов в корне. Для запуска платформа отдельно передаёт корпус и вопросы. Профиль строит поиск при старте и подходит для прогона без готового индекса.

## Запустить на настроенном прокси

Платформа передаёт `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` или их алиасы. Локально их задаёт пользователь. `TOP_K` принимает целое число от 1 до 30, по умолчанию — 5. Установите зависимости из `requirements.txt` в своё окружение. Затем из рабочего каталога, куда должен быть записан `submission.csv`, выполните:

```sh
DATA_DIR=/path/to/organizer-input python3 -B /path/to/casemtc/solution.py
```

Без доступа к прокси команда `python3 -B solution.py --demo` проверяет только CSV. Общий обработчик проверяется тестами с локальными фикстурами.

## Проверить тот же обработчик в вебе

Пример запуска из корня репозитория с уже настроенным API:

```sh
demo_dir=$(mktemp -d)
python3 -B -m examples.demo_web --db "$demo_dir/energytool.sqlite3" \
  --knowledge-base /path/to/organizer-input/knowledge-base.zip
```

По адресу [127.0.0.1:8080](http://127.0.0.1:8080/) работает локальная форма консультации. Ссылки на материалы раскрываются в блоке «Источники ответа». Для прогона используйте тестовые обращения и контакты. Команда без `--knowledge-base` запускает [синтетический сценарий](CONSULTATION_SLICE.md).
