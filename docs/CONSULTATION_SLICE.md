# Сценарий консультации по учёту в бизнес-центре

Текущий веб-чат запускается командой `docker compose up --build` и использует [API S1](contracts.md). Для сквозной проверки через выданную базу и прокси используйте [настройки Docker](I4_DOCKER.md) и [платформенный запуск](I3_SUBMISSION.md).

Команды ниже запускают ранний автономный пример из `examples/`. Его веб и CSV вызывают одну синтетическую функцию из `examples/demo_consultation.py`.

## Веб-чат

Из корня репозитория запустите демо. Нужен Python 3.11 или новее.

```sh
demo_dir=$(mktemp -d)
python3 -B -m examples.demo_web --db "$demo_dir/energytool.sqlite3"
```

Откройте [локальное демо](http://127.0.0.1:8080/), нажмите «Новый диалог» и отправьте по очереди следующие сообщения.

1. «Нужен учёт по арендаторам, счётчики уже установлены».
2. «Часть показаний получаем по фото, часть снимает техник. С чего начать?»
3. «Не готов оставить телефон. Что подготовить?»
4. «Перезвоните, пожалуйста».

На третьем шаге чат продолжит консультацию. На четвёртом он покажет резюме. Введите тестовый номер `+70000000000` и сохраните заявку. Подтверждение означает запись в локальную SQLite. Новый диалог открывается с пустой историей. Старый доступен по своему адресу и сохраняется при перезапуске с тем же файлом SQLite. Демо слушает только `127.0.0.1` и предназначено для синтетических диалогов и контактов.

## CSV

Из корня репозитория создайте отдельный временный каталог для входа и результата.

```sh
repo_dir="$PWD"
demo_dir=$(mktemp -d)
cat > "$demo_dir/questions.csv" <<'CSV'
id,question
015,"Пользователь: Нужен учёт по арендаторам, счётчики уже установлены.
Ассистент: Как сейчас собираете показания?
Пользователь: Часть показаний получаем по фото, часть снимает техник. С чего начать?"
other,С чего начать?
CSV
(
    cd "$demo_dir" || exit 1
    DATA_DIR="$demo_dir" PYTHONPATH="$repo_dir" python3 -B -m examples.demo_consultation
    cat submission.csv
)
```

Строка `015` получает тот же ответ, что веб-чат на втором шаге. Строка `other` начинает отдельную консультацию. Существующий `solution.py --demo` по-прежнему проверяет только формат CSV.

## Контракт для интеграции

- Ядро принимает историю из `Turn(role, text)` с последней репликой пользователя. Веб получает роли из сессии. CSV распознаёт метки `Пользователь:` и `Ассистент:` из примеров организаторов и передаёт каждую строку в отдельный вызов.
- `Reply` содержит текст, следующее действие, необязательное резюме и идентификаторы использованных материалов. В этом примере идентификаторы синтетические.
- Адаптер веба хранит историю и сохраняет заявку после явного подтверждения. Адаптер CSV пишет только `id,answer`.

Автоматические проверки запускаются командой `python3 -B -m unittest discover -s tests -v`.
