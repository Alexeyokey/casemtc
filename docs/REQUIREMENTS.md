## Платформенный контракт

По регламенту: DATA_DIR/questions.csv (id,question), выданный knowledge-base.zip; результат submission.csv в рабочем каталоге, только id,answer, по одному непустому ответу на ID. История внутри question может быть многострочной. Максимум ответа 10 000 символов; обычно до 150 слов.

Письменный регламент при текущей сверке всё ещё допускает в ZIP только корневые .py и закреплённый requirements.txt, запрещая данные/индексы/конфиги/whl и runtime pip install. На Q&A **41:49–42:32** организаторы устно разрешили включать готовый индекс при размещении файлов **в корне**, без подпапок. Это уточнение зафиксировано в [QA01](ORGANIZER_QA.md#qa01); оно не является доказательством уже изменённого загрузчика платформы.

Поддерживаем `runtime` (построение из выданной БЗ при старте) и `precomputed` (явно перечисленные корневые файлы индекса/необходимых метаданных). Выбор второго для сдачи — после фактической проверки переноса и чтения файлов в I5. Резервный runtime-путь сохраняется; данные/веса/конфиги автоматически разрешёнными не считаем. Индексы закрытой БЗ не публикуем и не маскируем под Python.

Письменные лимиты остаются: **128 МБ ZIP, 8 CPU, 16 ГБ RAM, 20 минут, 5 отправок в сутки**. Устное отсутствие дополнительных квот прокси не отменяет bounded retries/concurrency и бюджет клиента. Нечёткая фраза о 64 МБ не заменяет письменные 128 МБ ZIP.

## Уточнения приёмки по Q&A

- [QA02–QA04](ORGANIZER_QA.md): одна консультация для посетителя без специальной роли; факты из выданной БЗ; вопросы зависят от контекста, фиксированной анкеты нет.
- [QA05–QA06](ORGANIZER_QA.md): предлагаем ФИО/телефон/компанию; при явном запросе обратной связи валидного телефона достаточно для нашего пути сохранения. Отсутствующие поля не придумываем. Без контакта продолжаем помощь и сохраняем историю. CRM/почта не обязательны; результат — человекочитаемые контакты и актуальное резюме.
- [QA07–QA08](ORGANIZER_QA.md): источники и время в переключаемом debug; архив всех сессий можно хранить локально с документированным чтением/экспортом. Отдельный архивный UI необязателен. Сохранность после restart — наш инженерный критерий, не обещание обязательного возобновления активного чата.
- [QA09–QA10](ORGANIZER_QA.md): ориентир ответа около 5–7 секунд, не новый жёсткий timeout; параметры API проверяем по фактическому контракту. Отдельный внешний тестовый прокси не обещан.
- [QA11–QA12](ORGANIZER_QA.md): демо — примеры; подробности скрытого судьи не обещаны. Web E2E до заявки обязателен отдельно от предположений об охвате автотестов. Порядок выбора private-архива и точное время защиты перепроверяем перед финалом.

## Допуск и оценка

Допуск требует одновременно положительного результата LLM-судьи, рабочего web-пути до заявки и полного комплекта сдачи. Онлайн: 50% автоматическая оценка и 50% экспертная. Автооценка: 70% Match Rate + 30% Win Rate, сравнение с baseline в двух порядках; public и private наборы различаются. Экспертные веса: работоспособность 30%, консультация 25%, скорость/стабильность 15%, архитектура 15%, безопасность/документация 10%, презентация 5%. Финал: результат онлайн-этапа 40%, защита 60%.

## Финальная проверка команды

- [ ] Выбранный профиль упаковки подтверждён допустимым запуском; устное разрешение индекса и письменное противоречие отражены в проверке I3/I5.
- [ ] Есть действительный положительный результат допустимого сабмита; демо-тесты не названы private golden.
- [ ] На чистом окружении воспроизводится Docker-запуск и web-путь до заявки.
- [ ] Истории без заявки сохраняются и доступны по инструкции; новый контекст изолирован, отдельный архивный кабинет не требуется.
- [ ] Проверены полная заявка, только телефон, неверный/исправленный телефон и отказ от контактов; сохранение не выдаётся за уведомление менеджера.
- [ ] Ошибки API/БД/повторы не теряют и не смешивают данные.
- [ ] Источники и ограничения проверяемы; нет выдуманных коммерческих обещаний.
- [ ] Репозиторий/ZIP/PDF совпадают с проверенным SHA; участники проверили локальные непопавшие коммиты.
- [ ] В PDF первый слайд содержит порядок проверки, repo и при наличии ссылку на UI.
- [ ] Жюри имеет доступ; действующие секреты и закрытая БЗ не опубликованы.

Источники требований: выданный PDF кейса, технический регламент, папка материалов и [Q&A организаторов с временными отметками](ORGANIZER_QA.md). В этот repo исходные материалы не загружались.
